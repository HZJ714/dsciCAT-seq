`Figure_S2.ipynb` reproduces the measured content of Figure S2 from the files the
analysis started from. Journal assembly (page geometry, panel letters, shared
colour key, compositing) is a production step and is deliberately **not** part of
the notebook.

> **Executed end-to-end 2026-10-23 (0 errors).** §4 ran at the 3k level with
> the `aricode` package as the scoring backend (20/20 seeds; failed workers are
> retried single-process — see §4). The remaining levels reused the delivered
> cache CSVs, and every number §5/§6 printed matched the delivered values to
> machine precision (per-seed max|ΔNMI| = max|ΔARI| = 0 across all 8 levels;
> the §6 paired test reproduced all 37 types and all 16 marked labels exactly).
> §1a derives the 269-cell COP/NFOL split from the pre-split object and

## The two steps everything depends on

Figure S2 is the only figure in the set that rests on **two different objects**,
and the notebook keeps them apart instead of papering over it:

```
A–B   3k_dsci_ht_10x_gs_subset.RDS      70,643 nuclei, 3 technologies, WNN
          └─ §1b  cell_type_updated = cell_type, except RNA_snn_res.1 == 34 -> COP/NFOL
                  (280 cells, 33 types) + technique (50k+100k -> dsciCAT-seq)
                  + the shared order / numbering / palette (= Figure 2's)

C–D   3k_dsci/3k_dsci_full.RDS          59,962 cells, dsciCAT-seq only (FY13 + FY14)
          └─ §1a  cell-level split  old Oligo & (Gpr17 > 0 | Bmp4 > 0) -> COP/NFOL
                  (269 cells, 0.45 %, 37 types) = the truth the down-samples draw against
          └─ §4   160 independent re-analyses (8 levels × 20 seeds)
```

`3k_dsci_ht_10x_gs_subset.RDS` is taken as given: how the per-technology matrices
become it (RNA+ATAC pairing, harmony WNN integration, clustering, the 32-type
annotation) is `Figure_2.ipynb`, and this notebook starts from the object. The one
relabelling S2 does depend on — COP/NFOL — is re-derived here in both objects
(§1a, §1b) from stored data, not from a hand-edited table.

The two COP/NFOL counts differ (280 vs 269) because the two objects differ, not
because one is stale: the throughput experiment runs on the deep
single-technology libraries alone, since "how many cells must I buy" is only
meaningful there.

## Two things a reader will ask, answered in the notebook

* **Why 20 seeds** — a rare type's single-seed `detected` flag is a coin flip:
  measured in the original single-seed pass, COP/NFOL was recovered at 5k (15 of
  22 cells in a 21-cell cluster) and *not* at 10k (all 21 absorbed into a
  1,008-cell Oligo cluster). Both runs are valid; 0.45 % sits exactly on the
  resolution boundary. The same seed list at every level is what makes §6's
  paired test possible.
* **Which NMI** — `aricode::NMI` defaults to `variant = "max"`, not the familiar
  MI/√(H·H). Panel C is the "max" series: 0.726 at 3k, versus 0.806 under
  "sqrt" (ARI unaffected). A panel-C shift of ~0.08 at every level with ARI
  unchanged is that, not a biology change.

## Requirements

R ≥ 4.1 with `Seurat` ≥ 4, `harmony`, `ggplot2` ≥ 3.4, `dplyr`, `tidyr`,
`stringr`, `pals`, `parallel`; `aricode` ≥ 1.0.1 for §4's scores (used as the backend on 2026-10-23;
if absent the notebook falls back to the verified embedded implementation, and
NMI stays on the same `variant="max"` scale); `ggtext` only for panel D's red
labels (without it the 16 marked labels get a `+` suffix). Python ≥ 3.8 with `numpy` +
`pandas` + `IPython` for running the notebook. Nothing is displayed inline:
figures are saved and reported by `show()` (the notebook stays small on GitHub).
Versions are printed by §0.4.
